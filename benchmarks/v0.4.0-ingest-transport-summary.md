# v0.4.0 Ingest Transport Summary

Reference run date: **April 6, 2026**

Reference machine:

- `uname -a`: `Darwin macbook 25.4.0 ... arm64`
- CPU: `Apple M4 Pro`
- Toolchain: `nix develop -c zig version` -> `0.15.1`

These numbers are a checked-in preview-readiness baseline, not a performance promise. The main purpose is to keep the local-ingest transport honest relative to the real live HTTP path.

## Commands

```sh
nix develop -c zig build bench-ingest-transport -- --scenario one_hot_one_writer
nix develop -c zig build bench-ingest-transport -- --scenario fanout_four_writers
nix develop -c zig build bench-ingest-transport -- --scenario warm_declared_10k
nix develop -c zig build bench-ingest-transport -- --scenario cold_declare_10k
nix develop -c zig build bench-ingest-transport -- --scenario steady_state_100k
```

Benchmark notes:

- The HTTP lane now uses the real `sydradb serve` process and `POST /api/v1/ingest`.
- The server-side large-body crash under `Expect: 100-continue` was fixed during this pass.
- The benchmark client suppresses `Expect:` on the HTTP POST path so the output stays single-response and machine-parseable.
- The warm UDS scenarios predeclare series before the timed append window; the declaration counters are still captured in the metrics columns below.

## Gate Readout

The current preview-promotion gates were:

- warm UDS within 25% of direct-engine throughput on the same scenario
- warm UDS at least `1.5x` faster than live HTTP on same-host workloads

Observed results:

- `one_hot_one_writer`: pass on both gates
  - UDS is about `88%` of direct engine
  - UDS is about `8.54x` faster than live HTTP
- `fanout_four_writers`: pass on both gates
  - UDS is about `89%` of direct engine
  - UDS is about `1.64x` faster than live HTTP
- `warm_declared_10k`: mixed result
  - UDS is effectively equal to direct engine
  - UDS is only about `1.24x` faster than live HTTP
- `steady_state_100k`: pass on both gates
  - UDS is about `97%` of direct engine
  - UDS is about `8.29x` faster than live HTTP

## Conclusion

The local socket path is clearly the better same-host exact-series transport in hot and sustained workloads, and it stays very close to direct-engine throughput when declarations are warm.

The remaining blocker to calling it fully “preview-recommended” is the `warm_declared_10k` gate miss: same-host UDS does not yet clear the `1.5x` advantage threshold over live HTTP for the high-cardinality warm append case. That means the right next step is still exact-series performance work, not widening the socket scope to market ingest or extra client SDKs.
